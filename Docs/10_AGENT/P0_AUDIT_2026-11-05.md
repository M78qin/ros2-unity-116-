## 1. 一句话结论

工程**已经具备"论文可用的交互与面板雏形"**（R2/R3 双主面板 + A1 漫游/射线/渐变 + A2 IK ghost 预览，均有自动自检证据），但距离参考 Skill 定义的"浏览器式工作台"差三件东西：**窗口化（可拖动/八向缩放/浮窗）**、**输入与刷新的统一仲裁**、**数据语义与性能可测量化**；同时场景里沉淀了大量**遗留 UI 与 955 个失联组件**，且今天场景被外部重存过一次（§4-P0-12）。

**不建议大重写。** 建议在现有 R3 shell 与 `TwinUiPipeline`/`TwinUiSnapshot` 契约上做**三层增量**：`WindowHost`（窗口化）+ `InputArbiter`（输入所有权）+ `UiBudget`（刷新/绘图预算），并把"论文第四章 4.6 实验"所需的数据侧（A35 收帧修复、E2/E3 正式重复）排在视觉改造之前。

## 4. 关键问题（按严重度）

### P0-1 双 active MainCamera 全场景渲染（严重）
- 证据：两个 active 相机 `cullMask=4294967295`、`depth=-1`、tag 均 `MainCamera`（`logs/p0_canvases_cameras.txt`）。
- 影响：GPU/带宽至少翻倍；`Camera.main`（18 处调用）解析不确定 → 射线/rig/UI 相机绑定可能"今天对、明天错"；UI Canvas 目标相机指向其中一个，切换后可能整屏黑。
- 论文影响：性能章节无法给出可信帧率；截图可能来自错误相机。
- 建议：P1 之前先定"唯一渲染主相机 + 一个可选 UI 相机（只渲染 UI 层）"；给机器人/工位/电池包分配专用 Layer。

### P0-2 13 个 Canvas / 4 个 active（含 3 个遗留 WorldSpace 面板）（严重）
- 证据：`logs/p0_ui_detail.txt`；`panel1`、`panel2_R`、`panel2_R (1)` 为 RenderMode 2。
- 影响：常驻渲染 + 遮挡 3D + GraphicRaycaster 命中面扩大；`UI/18` 的 3D 视觉证据只能靠"单帧隐藏两个全屏 Canvas"取得（见 `ik/README.md` 边界），说明**当前 Play 下 3D 被全屏 UI 遮住**。
- 建议：P1 只保留 `UI_二期面板` 为屏幕空间主窗；遗留面板先禁用/归档（需你确认，见 §11-Q2）。

### P0-3 全屏 UI 遮挡 3D 工位（严重，直接违反"3D 是主角"）
- 证据：A2 README「Play 下全屏 UI 覆盖 3D，3D 视觉证据仅 s06（单帧隐藏 2 个全屏 canvas）」。
- 影响：论文截图与演示看不到机械臂；与参考 Skill §2.1/§10-UI-01 直接冲突。
- 建议：主窗默认**非全屏宽窗 + 右侧停靠**，左侧留 3D 视区；这是 P1 的核心验收项。

### P0-4 无窗口化能力（严重，工作量最大）
- 证据：场景无 WindowHost/ResizeHandle/DockZone 组件；UI 为固定布局（`TwinUIPlayBuilder`/`TwinUIR3Builder` 生成）。
- 影响：论文演示与实验操作时无法"边看曲线边看机械臂"；参考 Skill 的 P1–P2 全部缺失。
- 建议：新建 `TwinUiWindowHost`（拖动/八向缩放/最小尺寸/布局持久化）+ `ITwinUiWindowContent` 接口，先包 **1 个主窗 + 3 个浮窗**（关节/TCP/曲线），不做通用窗口系统。

### P0-5 输入所有权未统一（高）
- 证据：`TwinPlayCameraRig`（右键+WASD、滚轮调速）与 `TwinPlayIkHandle`（左键拖动、X/Y/Z、Esc）各自用 `IsPointerOverGameObject` 判 UI；窗口拖动尚不存在；`SmartRaycaster` 仍在（运行期被禁用）。
- 影响：一旦加窗口拖动/缩放，右键与滚轮必然冲突（参考 Skill §2.4 硬约束）。
- 建议：`TwinUiInputArbiter`（栈式所有权：Modal > WindowDrag/Resize > UI > IK > Ray > Camera），所有输入消费者改为向仲裁器申请/释放。

### P0-6 刷新与绘图无预算（高）
- 证据：6 图表每次更新 `SetVerticesDirty()` 全量重建（无降采样证据）；`TwinUiSnapshotExport` 5 Hz 主线程写 JSON（含 `File.Delete`+`File.Move`）；10 Hz 应用 + 30/60 Hz 采样共存。
- 影响：Editor 已见 60 Hz 档只有 50.3 Hz（84%）；接真机数据流 + 图表满屏时帧率风险未知。
- 建议：`UiBudget` 配置（采样/应用/绘图三级 Hz + 每帧最大重绘数 + 图表点数上限 + 导出改后台线程/降低频率），并接入 Profiler 基线。

### P0-7 数据语义未贯穿（中高）
- 证据：`TwinUiSnapshot` 有 `TwinUiSourceKind`，但 `Unavailable/Stale/Estimated` 未在全部控件上强制；A1 日志出现 `binder snapshot hasFrame=False connected=False`（无数据时仍渲染数值位）。
- 影响：论文"数据真实性"章节（第五章/4.5）会被质疑；参考 Skill §5.1 明确禁止"假 0"。
- 建议：给每个数值控件统一 `TwinUiValueState`（Actual/Target/Estimated/Unavailable/Stale + 时间戳），契约层强制，控件层渲染 `—`。

### P0-8 实验 UI 两套并行（中高）
- 证据：`Ros2ExperimentPanel`（810 行，场景挂载）vs `ExperimentSessionController`（709 行）+ `TwinPaperRecorder`（883 行，未挂载）；`TwinRecorder` 场景 ×2。
- 影响：E2/E3/E5 的"哪套录制器产出的 CSV 算正式数据"无法自证；A35 收帧问题也可能与两条链路并存有关。
- 建议：P6 先做**数据侧收敛**（选一套记录器为唯一正式出口 + 写进 `evidence_register`），再做 UI 呈现；这也正是论文 4.6 的前提。

### P0-9 双向控制只到 Preview（中）
- 证据：A2 `allowRobotDispatch=false`，`UI/18` 断言零下发；无 PLAN/VERIFY/READY 状态 UI。
- 影响：论文"双向控制"章节只能写"预览级"，不能写"执行级"（除非 A40 完成 + 真机授权）。
- 建议：P5 只做**状态机可视化 + 授权门禁 UI**，默认仍 `dispatch=0`；真机执行单独立项（依赖 A35 修复 + 安全评审 + 用户授权）。

### P0-10 无性能基线/无可测量性（中高，贯穿所有阶段）
- 证据：无 Player Build 数据、无 Profiler 记录、无 Canvas batch/rebuild 指标（§2.9）。
- 影响：任何"优化"无法验收；参考 Skill §4.5/§10 要求先基线。
- 建议：P0 收尾即立"性能采集工具 + 6 场景矩阵"（§8），所有后续阶段附数字。

### P0-11 场景资产债务：955 个失联组件 / 162 个 Outline / 遗留 Canvas（中）
- 证据：710 个 `m_Script` 无 guid + 245 个引用 12 个全工程不存在 guid（`logs/p0_missing_scripts*.txt`）；GO 名集中在 `Label/Value/Bar/State/Bg/Text/Error/Target/Current/Title/Line/Dot` → 疑似**已删除的自定义 UI 框架**残留。

- 建议：P1 做一次"只读清单 + 分批清理"（先备份、后禁用到单独父节点、再删），并保留 GUID 台账。

```

   ▼

   ├─ Desktop Presenter（现有 R3 shell：TwinUiIndustrialHost + 各 View）
   │      └─ TwinUiWindowHost（新增：拖动 / 八向缩放 / 最小尺寸 / 布局持久化）

   ▼
控制呈现  TwinCommandController（已有）→ Preview / Plan / Verify / Authorized（P5 仅可视化 + 门禁）
```

**关键契约（新增/收敛，不破坏现有）**
1. `ITwinUiWindowContent`：`MinSize`、`Title`、`OnShow/OnHide`、`Refresh(UiBudget)`。
2. `TwinUiInputArbiter.Request(owner, priority)` / `Release`：所有消费者（rig/IK/window/ray）必须申请。
3. `TwinUiValueState`：数值 + 状态 + 源时间戳 + 单位；控件按状态渲染（`Unavailable → "—"`）。
4. `UiBudget`（ScriptableObject）：`sampleHz/applyHz/drawHz`、`maxPointsPerChart`、`maxRedrawsPerFrame`、`snapshotExportHz/threading`。
5. 场景 Layer 契约：`Robot/Workcell/Battery/Pick` 专用层 + 射线 mask，替换 `mask=19`。

## 13. 审计纠正（2026-11-05 21:43，P1b-1 实测后）
